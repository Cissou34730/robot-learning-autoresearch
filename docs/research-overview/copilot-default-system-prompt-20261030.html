What enters the model context in a default Copilot SDK session

This page lists the standard Copilot SDK behavior, not this harness's settings. Probe: Copilot SDK 1.0.26, Copilot CLI 1.0.103, Windows, 30 October 2026. Each session used the default options and one short turn. The probe folder was a Git repository that contained AGENTS.md and .github/copilot-instructions.md. The SDK reports each prompt section to a transform callback, and the probe recorded the full system message from the system.message event.

How you can change the system prompt

SDK mode Result
append (default) The full CLI prompt below, with your text added at the end.
customize The CLI prompt, with per-section actions: replace, remove, append, prepend, preserve or a transform callback that receives the section text and returns new text. There are 12 section IDs. A part inside a section has no ID of its own: you change it only with a transform of its section, or with an action on the whole section.
replace Your text only. Every row of the first table disappears. The tools of the second table do not disappear, because the model receives them as function definitions, not as prompt text.

3. Parts that can enter but did not appear in this probe

The SDK describes these parts, but the probe had nothing to load for them:

  • Memories, workspace context and content-exclusion policy, all in runtime_instructions. Options: section runtime_instructions and memory.
  • Subagent model preferences (<subagent_model_preferences>), in last_instructions when the task tool is offered and preferences exist.
  • Skills: there was no skill tool in this probe. Options: enable_skills, skill_directories, disabled_skills.
  • Custom agents, from custom_agents or from discovered agent files. Option: enable_config_discovery.
  • Other instruction files found through instruction_directories.

4. Client option mode="empty"

The SDK has a second client mode: CopilotClient(mode="empty"). The default is mode="copilot-cli", which this page describes. The option exists in SDK 1.0.11, 1.0.19 and 1.0.26. Empty mode does not remove the system prompt. It changes the defaults of other session options. A value that you give explicitly always wins.

The harness does not use empty mode. It sets most of these options one by one, and it uses replace mode for the PI and analyst prompt. Empty mode would not change that prompt or the tools offered. Before any switch, check the keychain effect on sign-in with the logged-in GitHub user.

Families and limits of this probe

  • GPT-6: gpt-6-luna. GPT-5.6: gpt-5.6-luna, the same as GPT-6 except one code rule. GPT Codex: gpt-5.3-codex.
  • Claude: claude-sonnet-5.5 and claude-haiku-5.5 gave the same text apart from the model name.
  • Other: mai-code-1.1-flash (Copilot) and opencode-go/deepseek-v4.1-flash (your own provider) gave the same text apart from the model name.
  • The probe did not test GPT-6.1, Claude Opus, Claude Fable or Gemini. On Linux or macOS the shell block is for a different shell. The tool list depends on the plugins and MCP servers installed on the machine.
  • The probe scripts and captured texts are outside the repository, in %TEMP%\robot-learning\default_prompt_probe.py and %TEMP%\robot-learning\default-prompt-probe\.
